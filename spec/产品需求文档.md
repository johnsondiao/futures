> 版本：v2.3
> 变更说明：
> - v2.0：新增多策略支持与策略选择页（含盈利预期）。
> - v2.1：曾另立「App 内参数自定义与实时回测」需求（F7）。
> - v2.2：**按产品分工修正** —— 恢复双端定位：**PC 端负责策略回测与最佳参数寻找，安卓端负责策略开仓提醒**；原 F7（App 内实时回测）与分工冲突，降回备忘项。

## 1. 产品概述

### 1.1 定位与分工

一套「趋势通道」交易系统的两个产品部分，通过**策略规则定稿**与**统计数据文件**衔接：

| 部分 | 职责 | 形态 |
|------|------|------|
| **PC 端** | 策略回测、参数搜索与最佳参数寻找、稳健性验证；生产各策略的回测统计供安卓端展示 | Python 命令行工具链 |
| **安卓端** | 策略开仓提醒：行情盘面 + 策略选择（含盈利预期展示）+ 新开仓信号声音/通知提醒 | Android App |

衔接约定：

- PC 端选定最佳参数 → 写入 `spec/交易规则_定稿.md`（唯一权威规则文本）；
- PC 端回测统计 → 导出为 `assets/strategy_stats.json` 随 APK 打包，供安卓端策略选择页展示盈利预期；
- 安卓端**不做回测、不调参**，只消费 PC 端产出的策略与统计（永久边界，见 §7）。

产品整体**不自动下单**：系统给出信号与条件单建议，由用户在期货软件手动执行。

### 1.2 核心策略规则（双端共用）

- 标的：豆一 `DCE.a2611`（App 内可配置，见 F5-3），周期 **5 分钟**，固定开仓 **3 手**
- 规则详见 [`spec/交易规则_定稿.md`](./交易规则_定稿.md)，要点：

| 环节 | 规则 |
|------|------|
| 通道 | 上轨 `MA(最高价,60)`、下轨 `MA(最低价,60)`；收盘>上轨=红，收盘<下轨=绿，通道内保持原色 |
| 开仓 | 通道变色后，等 CCI(15) 与其 MA(4) 金叉/死叉确认，同向开 3 手（mode=`color_then_cci`） |
| 止盈 | ATR(20) 滚动，1.5 / 3 / 5 倍各平 1 手（收盘价判定） |
| 止损/清仓 | 反向变色即平剩余仓位 |

### 1.3 目标用户

个人期货交易者（单用户自用）：PC 端做策略研究与选参，手机端盯盘收提醒后手动下单。

## 2. 策略体系

### 2.1 策略定义

一个「策略」= 入场规则 + 出场规则 + 参数集 + 回测统计。字段：

| 字段 | 说明 |
|------|------|
| `id` | 唯一标识（如 `color_then_cci`），双端实现与对拍以此为准 |
| 名称 / 一句话简介 | 展示在安卓端策略卡片 |
| 规则详情 | 入场、止盈、清仓的文字说明与参数表 |
| 回测统计 | **盈利预期（净利）**、胜率、平仓笔数，由 PC 端产出（§2.3） |

**公共出场规则**（所有策略共用，除非策略单独声明）：ATR(20) 滚动止盈 1.5/3/5 倍各平 1 手；反向变色平剩余。

### 2.2 首期策略清单

沿用回测引擎已实现的入场模式，首期 5 个：

| id | 策略名称 | 入场规则 | 定位 |
|----|----------|----------|------|
| `color_then_cci` | 通道变色 + CCI 确认 | 变色后等 CCI 金叉/死叉确认再开仓 | **默认策略**（定稿，稳健区域） |
| `color_only` | 通道变色即入 | 变色当根即开仓 | 信号最快，假信号偏多 |
| `color_and_cci` | 变色同根 CCI 确认 | 变色当根同时满足 CCI 同向 | 更严格，信号更少 |
| `cci_cross_only` | 仅 CCI 交叉 | 不看通道，CCI 金叉/死叉即开仓 | 震荡市信号密集 |
| `cci_then_color` | CCI 先行再变色 | CCI 先交叉，再等通道变色确认 | 与默认策略互为镜像 |

新增策略流程：PC 端实现并回测出统计 → 安卓端 JS/Kotlin 双端实现 → 对拍一致 → 随版本发布。

### 2.3 盈利预期数字

| 项 | 规定 |
|----|------|
| 定义 | 该策略在**样本内回测**（DCE.a2609 / 5m / 固定 3 手 / 既定样本区间）的净盈亏，单位：元 |
| 数据来源 | **PC 端回测工具产出**，导出为 `assets/strategy_stats.json` 随 APK 打包；安卓端不在线计算 |
| 展示 | 策略卡片大字号展示；正数盈利色、负数亏损色；千分位；缺失显示「—」；胜率/笔数为次要小字 |
| 更新机制 | PC 端重新选参/回测 → 更新 JSON → 随新版本发布；发版检查项含「统计与策略版本匹配」 |
| 免责标注 | 数字旁固定标注「样本内回测参考，不保证实盘收益」 |

## 3. 功能需求 —— PC 端（策略回测与最佳参数寻找）

### F1. 行情数据获取与缓存（`src/data/`）

| 编号 | 需求 |
|------|------|
| F1-1 | 通过天勤 TqSdk 拉取指定合约、周期（5m/60m/1d）、根数的 K 线；账号从 `.env`（`TQ_USER`/`TQ_PASS`）读取 |
| F1-2 | 结果落盘缓存（`pc/data/cache/{交易所}_{合约}_{周期}.csv`），重复回测优先读缓存；无网络时可离线回放缓存 |
| F1-3 | `.env` 缺失时给出明确报错而非崩溃 |

### F2. 策略回测（`pc/scripts/run_backtest.py` + `strategies/channel_trend.py`）

| 编号 | 需求 |
|------|------|
| F2-1 | 命令行入参：`--symbol --period --bars --cash --mode --printlog`，默认 `DCE.a2611 / 5m / 8000 根 / 100 万资金` |
| F2-2 | 严格按 §1.2 规则执行：变色→CCI 确认开仓、ATR 三档分批止盈（收盘价判定、滚动 ATR）、反向变色清仓 |
| F2-3 | 支持全部入场模式切换（§2.2 的 5 个 id），供搜索对比 |
| F2-4 | 输出终值、成交摘要（总笔数/胜负/净盈亏）与 Analyzer 统计；手续费模型：比例约 0.00015、乘数按豆一 10 |

### F3. 最佳参数寻找（核心职责）

| 编号 | 需求 |
|------|------|
| F3-1 | `pc/scripts/goal_search.py` / `goal_search_full.py`：网格穷举（当前 17880 组），断点续跑，逐组写 `pc/data/goal/search_log*.jsonl` |
| F3-2 | `pc/scripts/scan_atr_winrate.py`：固定入场逻辑后扫描 ATR 止盈倍数组合，输出胜率/净利对比 |
| F3-3 | `pc/scripts/robustness_report.py`：按入场逻辑分组输出「该组参数是否全部盈利」的稳健性报告；**选参原则是稳健区域而非单点最优** |
| F3-4 | 产物：`pc/data/goal/best*.json`、`summary*.json`、`robustness_report_*.txt`；选定结果回填 `spec/交易规则_定稿.md` |

### F4. 统计导出与对拍（供安卓端消费）

| 编号 | 需求 |
|------|------|
| F4-1 | 统计导出：按 §2.3 口径为每个策略生成净利/胜率/笔数，写入 `android/.../assets/strategy_stats.json`（新增导出脚本） |
| F4-2 | 信号对拍：`pc/scripts/export_strategy_compare.py` + `node pc/scripts/compare_strategy.mjs`，验证安卓端 JS/Kotlin 实现与 Python 口径信号一致；每个策略发版前必须零差异 |
| F4-3 | 回测可视化（`pc/scripts/export_chart.py`）：导出 HTML 回测图（通道/变色/开平仓标记）、权益曲线 PNG、成交明细 JSON，供选参复盘 |

## 4. 功能需求 —— 安卓 App（策略开仓提醒）

### F5. 账号与行情接入

| 编号 | 需求 |
|------|------|
| F5-1 | 首次使用输入天勤账号/密码登录（与快期同一套账号） |
| F5-2 | 凭据用 EncryptedSharedPreferences（AES256）仅存本机，不上传任何自建服务器 |
| F5-3 | OkHttp WebSocket 直连天勤 DIFF 行情网关（无官方 Android SDK，自实现底层协议）；订阅设置页「交易品种」配置的合约（默认 `DCE.a2611`）5 分钟 K 线 |
| F5-4 | 鉴权过期：前台时回登录界面重登；后台时 Service 用保存凭据静默自愈重登 |
| F5-5 | 断线自动重连（5s 延迟）；下拉手势手动重连；网络恢复主动重连 |

### F6. 策略选择页（含盈利预期）

| 编号 | 需求 |
|------|------|
| F6-1 | 入口：盘面顶部「策略」按钮；未选过时默认 `color_then_cci` |
| F6-2 | 卡片内容：策略名称、一句话简介、**盈利预期数字（大字号）**、胜率/笔数小字、「使用中」徽标 |
| F6-3 | 点按卡片展开规则详情（入场/止盈/清仓、参数表），含「使用该策略」按钮 |
| F6-4 | 选定结果持久化（EncryptedSharedPreferences），重启自动恢复 |
| F6-5 | 切换即时生效：盘面信号、条件单卡片、机会评估、原生后台检测全部切到新策略，无需重启 App |
| F6-6 | 盈利预期展示规则见 §2.3；负数与缺失（「—」）有明确样式；`strategy_stats.json` 损坏/缺失时页面可用、仅数字显示「—」 |
| F6-7 | 页面固定免责说明：「盈利预期为样本内回测结果，不代表实盘收益；App 不自动下单」 |

### F7. K 线盘面与信号展示（WebView，`assets/www/`）

| 编号 | 需求 |
|------|------|
| F7-1 | 5 分钟 K 线图表（lightweight-charts），叠加通道上下轨与红/绿变色 |
| F7-2 | K 线旁标注**当前所选策略**的「开多/开空」信号与止盈/平仓事件 |
| F7-3 | 条件单卡片：按状态（观望/等开多/等开空/持多 N 手/持空 N 手）给出条件单及价格（开仓触发、止盈三档、止损），含点数与 ATR 距离 |
| F7-4 | 机会评估区：当前信号偏多/偏空评估文案 |
| F7-5 | 「介绍」页：按所选策略展示规则说明与示意图；声明不自动下单、回测不保证实盘收益 |
| F7-6 | 盘面顶部显示当前策略名称，点击跳转策略选择页 |

### F8. 开仓信号提醒（核心价值）

| 编号 | 需求 |
|------|------|
| F8-1 | 触发条件：**当前所选策略**在 K 线上新出现「开多/开空」信号时触发（历史信号不打扰；去重） |
| F8-2 | 提醒形式可独立开关（设置页）：提示音、震动、系统通知、应用内横幅；另有总开关 |
| F8-3 | 「试听一次提醒」按钮：走与真实信号一致的提醒路径 |
| F8-4 | 通知失败时状态栏给出原因（权限未授予/渠道被禁/开关关闭） |
| F8-5 | 飞书兜底通道：配置自建应用机器人凭证后，即使系统通知被关仍私聊推送信号卡片（含时间、合约、周期、策略名称） |

### F9. 后台保活

| 编号 | 需求 |
|------|------|
| F9-1 | 切后台、熄屏后仍持续拉行情并按当前策略检测信号 |
| F9-2 | 实现：specialUse 前台服务 + PARTIAL_WAKE_LOCK（12h 上限、每小时续期）+ 60s AlarmManager 精确闹钟兜底心跳 + START_STICKY 被杀自启 |
| F9-3 | 检测在 Kotlin 原生层（`ChannelSignalDetector.kt`）运行，不依赖 WebView JS；前台时 bars 同时推给 WebView 渲染 |
| F9-4 | 前台/后台只响一次，避免双响 |
| F9-5 | 策略切换后原生检测器同步切换，无需重启服务 |

### F10. 分发与构建

| 编号 | 需求 |
|------|------|
| F10-1 | GitHub Actions 编译 APK，产出 debug 签名包 `channel-strategy-apk`，个人安装分发，不上架应用商店 |
| F10-2 | 环境约束：compileSdk/targetSdk=34，minSdk=24 |

## 5. 非功能需求

| 类别 | 要求 |
|------|------|
| 安全 | 天勤密码仅本机加密存储；`.env` 不进版本库 |
| 可靠性 | 行情断线 5s 自动重连；网络恢复主动重连；后台被杀 START_STICKY 自启并重登；PC 端搜参断点续跑 |
| 一致性 | Python（PC 基准）/ JS / Kotlin 三端策略信号必须一致，以 F4-2 对拍零差异为发版门槛；改规则需同步三端并更新定稿文档 |

| 兼容性 | App 支持 Android 7.0+ |
| 免责声明 | 盈利预期、策略介绍、提醒文案均注明：样本内回测结果，不保证实盘收益；不自动下单 |

## 6. 关键验收标准

**PC 端：**
1. `run_backtest.py` 正常输出终值与成交摘要，信号与交易规则定稿逐条对应。
2. 网格搜索可断点续跑；稳健性报告能区分「全部盈利」的稳健组与尖峰组。
3. 导出脚本生成的 `strategy_stats.json` 含全部策略的净利/胜率/笔数，与搜参产物数值一致。
4. 回测 HTML 图中可见通道变色、开多/开空、止盈 1/2/3、反向清仓标记。

**安卓端：**
5. 策略选择页：5 个卡片完整展示名称/简介/盈利预期/胜率；正负样式正确、缺失显「—」。
6. 策略切换：盘面信号、条件单卡片、机会评估即时变化；重启后恢复上次选择。
7. 信号一致：同一策略下盘面（JS）信号与后台原生提醒一一对应，且与 PC 端对拍零差异。
8. 前台提醒：新开多/开空标记按设置触发声音/震动/通知/横幅。
9. 后台提醒：熄屏 30 分钟后新信号仍响铃并通知（服务存活、WakeLock 未泄漏）。
10. 凭据与免责：抓包确认仅与天勤官方网关通信；盈利预期旁有免责文案。

## 7. 约束与风险

| 项 | 说明 |
|----|------|
| 安卓端不调参 | 参数自定义、回测、盈利预估均在 PC 端完成；安卓端仅消费 `strategy_stats.json` 与定稿规则，**不提供任何调参入口**（永久产品边界） |
| 不做自动下单 | 产品边界止于「信号 + 提醒 + 条件单建议」，不接入实盘报单 |
| 盈利预期的误导风险 | 数字为单一样本内回测结果，换合约/时段可能失效；必须以固定免责文案与「—」缺省态弱化承诺含义 |
| 统计滞后 | `strategy_stats.json` 随版本打包，PC 端调参后未同步更新会造成数字与规则不一致；发版检查项必含匹配校验 |
| 协议风险 | 天勤无官方 Android SDK，DIFF 接入属自研实现，网关变更时需适配 |
| 合约切换 | 合约已在设置页可配置（默认 `DCE.a2611`），换合约无需发版；但策略参数基于历史合约样本调优，新合约表现需自行验证 |
| 「禁止同色再开」规则 | 交易规则定稿中注明暂未启用 |
| 三端一致性成本 | 每新增/修改策略需同步 Python/JS/Kotlin 三份实现并对拍，是最大的维护成本项 |
